### 機能要件定義書：My Time
#### 1. 文書概要
*   **プロダクト名：**  My Time
*   **対象プラットフォーム：**  Android 17（古いAndroid端末との互換性問題が生じる場合は切り捨て可）
*   **開発環境：**  Windows 11 Pro / Android Studio / 必要に応じて VS Code（開発言語：Kotlin）
*   **最終目標：**
    *  ガクチカ用ポートフォリオとしての完成
    *  GitHubでのオープンソース公開（OSS化）
    *  GitHub Releases等を通じたAPK配布

#### 3. 機能要件詳細
##### 3.1 アラーム機能
###### F-01：アラーム登録・一覧・編集・削除
*   **登録上限：**  アラームの登録件数は  **最大30件**  とする。上限到達時は新規追加を制限し、理由を通知する。
*   **一覧表示：**  登録済みアラームの時刻、スケジュール、出力先モード、ON/OFF状態を確認できること。
*   **編集・削除：**  既存アラームの時刻・条件・出力先等の変更、および削除が行えること。
*   **状態切替：**  一覧画面から各アラームの有効／無効を即座に切り替えられること。
###### F-02：スケジュール指定（曜日／特定日）
*   **曜日繰り返し：**  月曜日〜日曜日のうち  **複数曜日を選択**  して繰り返し設定できること。
*   **特定日付指定：**  曜日繰り返しとは別に、 **日にちを特定**  した単発アラームを設定できること。
###### F-03：出力先選択（スピーカー／Bluetooth）
*  アラームごとに以下の出力先モードを選択できること。
    1.  **スピーカー固定：**  端末の内蔵スピーカーから出力する。
    2.  **Bluetooth優先（未接続時スピーカー）：**  Bluetooth接続時はBluetooth側へ出力し、未接続または接続が切れた場合は端末スピーカーへ切り替えて鳴動を継続する。
*   **OS制約の扱い：**  マナーモード等については、Android側の標準的な制約・挙動に従うこととし、本機能としての特別扱いは行わない。
###### F-04：スヌーズ機能
*  鳴動中にスヌーズを実行した際、以下の間隔指定に対応すること。
    *   **5分ごと**
    *   **10分ごと**
    *   **指定分数ごと** （任意の分数を指定）
    *   **指定時間ごと** （任意の時間を指定）
###### F-05：バイブレーション設定
*  アラームごとにバイブレーションの  **ON / OFF**  を個別に設定できること。
*  ON設定時はアラーム鳴動に合わせてバイブレーションが作動し、OFF設定時は作動しないこと。
###### F-06：カスタム音源設定（要確定事項）
*  アラーム音源の指定に対応すること。
*  端末内音源ファイルの探索機能（ファイルピッカー／ストレージ探索等）を組み込むかについては、実装フェーズで確定する。
###### F-07：鳴動中操作UI（スライド解除）
*  鳴動中の画面において、誤停止を防ぐための操作UIを設けること。
*   **スライド操作** による停止を基本とし、寝ぼけた状態での単なるタップ誤操作を防止できる構成とすること（長押し案はスライド採用を優先するため代替/補助位置づけ）。

--------------------------------------------------------------------------------

##### 3.2 タイマー機能
###### F-08：カウントダウンタイマー
*  時間を指定してカウントダウンを行い、終了時に通知・鳴動で知らせる機能を提供すること。
###### F-09：タイマー出力先選択
*  タイマー終了時の鳴動についても、アラームと同様に  **スピーカー固定**  または  **Bluetooth優先（未接続時スピーカー）**  の出力先を選択できること。

--------------------------------------------------------------------------------

##### 3.3 共通UI・テーマ機能
###### F-10：テーマ切替機能
*  アプリ全体のテーマを以下の  **4種類**  からユーザーが選択・切替できること。
    1.  **システムテーマ** （端末のシステム設定に追従）
    2.  **ライトモード**
    3.  **ダークモード**
    4.  **カスタムカラー（#DCD0FF）**

--------------------------------------------------------------------------------

##### 3.4 OSS公開・APK配布要件（最終目標）
###### F-11：GitHub公開・APK配布対応
*   **ソースコード公開：**  GitHubリポジトリにてソースコードを公開し、README（機能概要、ビルド手順、技術構成、ポートフォリオ説明）を整備すること。
*   **APK配布：**  リリース用にビルド・署名されたAPKファイルをGitHub Releases等から配布できる状態にすること。
*   **公開前チェック：**  個人情報、ローカル環境固有の秘密情報、不要なテストコード・未整理ファイルの混入を防止すること。
